# Minimax H3 — Techniques Reference

Knowledge base the `minimax-h3-storyboard` skill applies. Keep this current: when research surfaces better sources, fold the improvements in here.

## 1. Model capabilities (what to design around)

- **Two modes:** text-to-video and image-to-video. For character/look consistency across a multi-segment video, always prefer image-to-video with a **single reused reference image**, and repeat the identity line verbatim in every prompt.
- **Per-clip generation is a single continuous take.** Each generation is one short shot within a duration cap of up to **15s**. **A single long "one-take" clip — e.g. a 30s continuous shot — is not possible.** The model cannot render 30s in one generation; doing so will fail or loop/degrade. To produce a longer video you must split it into segments and generate + stitch each segment. Decide this in `project.generation_strategy`; default to `stitched-segments`, and only use `one-continuous-shot` when the total duration fits within a single per-clip cap (~15s or less).
- **Segment length discipline:** aim each segment at the full per-clip budget — **12–15s**, and only settle into **10–14s** when the beat genuinely can't sustain 15s. Never pad a timeline with throwaway **2–3s segments** just to split it up; push to the max, and only shorten when the action ends early. Longer segments also reduce the number of cuts the model has to render cleanly.
- **Camera and motion are described in prose**, not parameters. The model infers movement from natural-language description.
- **Audio IS generated by H3 together with the video.** Describe sound/music as complete generation instructions (fully stated instrumentation, tempo, and foley/ambience), not as a terse post-production reference.
- **Consistency is the hard problem.** The model drifts on face, wardrobe, and anatomy between clips. Lock identity, wardrobe, and world rules explicitly and repeat them.

## 2. Prompt structure (per segment) — ref2va rewrite

Authoritative format: `_ref2va_rules.md`; procedure: `SKILL.md` §5. Every segment prompt is a self-contained ref2va rewrite with six sections in this order: `subject_definitions`, `summary`, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music`.

Planning-level rules:
- `<Subject N>` = every visible subject (character, creature, environment-as-subject, key prop); cite the reference image inside the definition. `<Picture N>` only for a concrete frame anchor (provided first frame or environment key frame), never for a character-only sheet.
- `summary` opens with a bracketed task-type prefix (`[reference generation]`, `[keyframe completion]`, combined with ` + `).
- `retention_analysis` uses one line per label with `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`.
- `detailed_description` = locked style opening + shot-by-shot playback; timestamps relative to the segment's own start; scale to the ~12–15 s clip.
- Sound sections are generation instructions: fully describe ambience/foley and audience-only score; `N/A` only for deliberate silence.
- Write complete sentences; avoid keyword soup and empty superlatives.

## 3. Camera vocabulary

Use specific, combinable terms:

- **Angles:** low angle (power), high angle (vulnerability), dutch/tilted angle (unease, energy), eye-level (neutrality), POV, bird's-eye, worm's-eye.
- **Sizes:** extreme close-up, close-up, medium close-up, medium, medium full, full body, extreme wide / establishing.
- **Moves:** push-in (tension/reveal), pull-out (context/reveal), orbit/arc (drama), dolly (spatial), tracking/follow (movement), whip pan (speed/transition), tilt up/down, crane/jib, handheld (grit), static (stability).
- **Motion qualities:** slow / steady / accelerating / sudden / handheld / fluid. Pair a move with a speed and an amplitude; avoid contradictory instructions (e.g. "static" + "fast dolly").

Rule: the camera reveals the story and the subject, never obscures the main action. One focal point per shot.

**Camera kinematics formula.** Express every camera move as a full triple so H3 infers precise motion: `[Motion Type] + [Amplitude: with small/large amplitude] + [Speed: at slow/fast speed]` — e.g. "The camera pushes in with small amplitude at slow speed", "The camera pans right with large amplitude at fast speed". Never leave a move as a bare noun ("push-in") with no amplitude or speed; pair a move with an amplitude and a speed, and never contradict them (e.g. "static" + "fast dolly").

## 4. Motion grammar

Describe motion as a causal chain so the model stays physically coherent:

> primary action → fabric response → hair response → accessory response → environmental response → camera response

Examples:

- Head turn → loose hair strands follow with a slight delay → hem settles under gravity.
- A step → skirt shifts → hem trails behind → relaxes under gravity.
- A pause → residual motion in hair/fabric gradually dissipates.

Rules:

- Motion from the first frame — no slow build-ups unless the concept demands them.
- Keep each segment's action simple enough to render in one take; don't stack too many simultaneous actions.
- No impossible physics, no contradictory motion, no static-while-moving camera.

**Grounded, renderable action only.** Translate intent into physical micro-actions the model can actually render — eye-gaze direction, posture shift, muscle tension, and physical interaction with entities. Never write internal thoughts, speculative metaphors, or static-image buzzwords ("photorealistic", "8k", "masterpiece", "stunning") as if they drive motion; describe the visible body and the world instead. (Empty superlatives are already discouraged in §2 — prefer one coherent description over a list of adjectives.)

## 5. Identity & continuity preservation (the core of multi-segment work)

Generating segments separately and stitching them is where AI video usually falls apart: character faces drift, wardrobes change, backgrounds and lighting don't match, props morph, and each clip feels like a different shoot. Plan continuity deliberately. Methods ranked roughly by reliability:

### A. Reference images / image-to-video (most reliable — do this)

- Generate **one canonical base image per subject** (character, main environment, key props) with **Z-Image Turbo** (this project's sheet renderer; prompt rules in `_z_image_turbo_rules.md`). H3 is a video model: it consumes references, it does not make them.
- Feed **that same image as a reference** into every segment's H3 image-to-video job, reusing the identical image every time. Use it as the literal first frame only when the planned opening composition matches that sheet; otherwise let the planned cinematic cut define the opening. Image-to-video preserves the input image's identity far better than text-to-video.
- If the tool exposes a reference-strength/weight parameter, use a **high weight for character-locked shots**, lower for environment-only shots.

- **CRITICAL — images must live in ComfyUI's `input/` directory.** ComfyUI's `LoadImage` nodes (the nodes that load reference images into the workflow) **cannot traverse outside the input folder**. If a reference image is not already in `input/`, copy it there before submitting the workflow. The ComfyUI directory is `~/Documents/comfyui/`, so the input path is `~/Documents/comfyui/input/`. Example:

  ```bash
  cp ~/Documents/comfy_control/outputs/character_figure_front.png ~/Documents/comfyui/input/
  cp ~/Documents/comfy_control/outputs/env_dark_void.png ~/Documents/comfyui/input/
  ```

  If the image is not in `input/`, the `LoadImage` node will throw an error and the generation will fail — ComfyUI will not look elsewhere.

### B. Reference / turnaround sheets (lock the look before animating)

- **Determine the inventory first.** Count every **character**, every **prop**, and every **location** in the script, then generate exactly that many sheets (recorded in `references.inventory`). No character, prop, or location is left without a sheet.
- **Character turnaround sheet(s):** one per character — front / 3/4 / side / back views + signature expressions, in the exact locked wardrobe, on a neutral background. Biggest identity win for a multi-segment character piece.
- **Environment key frame(s):** one per location — the setting established once (lighting, palette, era), so background continuity holds.
- **Prop sheet(s):** one per prop (e.g. a straight sword), from multiple angles, so they don't change between segments.
- The skill provides the *prompts* to generate these sheets; you generate them with Z-Image Turbo, then feed the result to H3.

### C. Cinematic cuts (join segments by edit, not by frame-matching)

**Do NOT feed segment N's final frame into segment N+1 as its start frame.** Chaining clips frame-to-frame compounds drift: each clip re-interprets the previous one, so face/look/motion rot progressively across a multi-segment chain, and the result degrades the longer it gets. Instead, pros join segments with **intentional cinematic cuts on contrasting compositions**. Plan each cut deliberately so the edit reads as a professional decision, not a seam.

- **Straight cut (hard cut):** the cleanest, most common edit. Cut on the action or on a beat. End segment N on one composition and open segment N+1 on a *different* one — the contrast is what makes it read as a cut.
- **J-cut:** audio from segment N+1 (a line, an ambient shift, a sound effect, a music swell) begins *before* the visual cut — we hear the next beat arrive, then see it. Builds anticipation and smooths the transition.
- **L-cut:** audio from segment N *continues* into the opening beats of segment N+1 while the visual already changed — the previous scene's sound lingers over the new image.
- **Match cut:** connect two shots linked by a shape, motion, direction, or rhythm (a spinning blade → a spinning object; a character looking up → the thing they see). The shared element carries the eye across the cut.
- **Whip pan / action cut / cutaway:** use a fast motion or a brief cutaway as connective tissue when you need speed or energy.

**The composition-contrast rule (the heart of this):** end each segment on one framing/angle and open the next on a deliberately *different* one. Coverage alternates across a spectrum — e.g. end on a medium close-up, open the next on a wide / side profile / low angle; end wide, open close; end eye-level, open dutch. Shot/reverse-shot (face left → face right) is the workhorse for dialogue. The goal: no two adjacent segments share the same framing, so every cut is legible and never reads as a stuttered first-frame match.

**Head/tail signatures.** For each clip, name its **head signature** (how it opens — hard cut, whip-pan, motion match) and its **tail signature** (how it closes — the motion or composition the next clip's head answers). This makes every cut an intentional edit on contrasting framing rather than a blind splice.

Plan the cut in the storyboard with a `cut` object per segment (`type`, `description`, and a `composition_plan` of what the segment `ends_on` vs. what the next segment `opens_on`). Keep `transition_in` / `transition_out` describing the last beat and first beat the cut bridges. Continuity across the chain is then carried by **shared reference images (locked identity/look)** and by the **editing rhythm**, not by frame-matching.

### D. Prompt-based locking (necessary but not sufficient — we already do this)

- Verbatim canonical identity line copied into every segment prompt.
- **Full-package identity.** Treat the character, their complete wardrobe, and all accessories as one indivisible visual package — name anatomy, facial features, hair, silhouette, layered garments, fabric weaves, tailoring/seam lines, footwear, and wearable accessories together. Restate the whole package verbatim in every segment so nothing silently drops (a dropped earring, a missing sash) between cuts.
- Single wardrobe — no costume changes; name exact garments, colors, accessories.
- Locked lighting direction and environmental layout across all segments.
- World rules as immutable constraints (e.g. "no new characters," "monochrome ink palette," "no modern objects").
- Stable anatomy — specify proportions once; forbid extra limbs, wrong finger counts, morphing.

### E. User-provided vs. generated references

- Sheets are **always generated for all three types** (character, environment, prop) — see the skill's Step 2. Determine the inventory up front (how many characters, props, locations) and produce one sheet entry per item, regardless of source.
- If the user (or the source material) supplies a usable reference image for a subject, **use it as that subject's anchor** and cite it as `source: "user-provided"` — but still record the sheet entry so the inventory is complete. Do not drop a subject from the manifest just because a reference already exists.
- Generate (with an image model) the sheet for any subject that has no usable provided reference.

### F. Heavy options (optional, when identity is mission-critical)

- **Seed locking** (same seed across clips) helps marginally.
- **ControlNet / pose control** locks composition between clips.
- **Fine-tuning a LoRA** on your character is the gold standard for identity but is heavy training work — usually outside a planning-only workflow.

### G. 360° spatial continuity (lock the location, don't let it drift)

Environments drift the same way faces do: segment 1's boutique can quietly shift by segment 2 (different shelving, changed lighting, a window that moved), so stitched clips read as *different rooms*. Prevent it — an environment key frame is not enough on its own.

- **360° environment sheet.** Establish the location across all four cardinal views — 0° Front, 90° Right, 180° Reverse/Back, 270° Left — as one key-frame set (or a 4-panel turnaround grid). The model must be able to rebuild the room from *any* angle, not just the front it was shown.
- **Fixed landmarks.** Name 2–3 permanent architectural anchors per location (a chandelier, a display wall, a doorway) and reference them in **every** segment's prompt so the model rebuilds the same room, not a similar one.
- **Locked light direction + palette.** Keep the key-light direction and color palette identical across every segment; a shift in shadow direction or warmth is the fastest tell of a drifted background.
- **Reuse the environment as a `<Subject>`** in every segment's prompt (not only segment 1), citing the same key frame, so the background is carried by shared reference — never reinterpreted.

### Continuity manifest

Maintain a short table mapping each subject → its reference image file → which segment IDs reuse it → reference weight. This is the operational backbone that ties the segments together; the storyboard/plan should include it so the generator never has to guess which image to reuse.


## 6. Negative constraints (禁止项)

Applies to H3 video prompts. Z-Image Turbo sheet prompts are strictly affirmative and must contain zero negations (`_z_image_turbo_rules.md`). The ref2va format has no separate negative field, so encode H3 constraints as explicit world rules/avoidance lines inside the relevant section.

Write focused, shot-specific forbidden lists rather than a generic dump. Prioritize the failure modes most likely for that shot:

- Anatomy: extra/missing limbs, wrong finger counts, morphing, impossible poses.
- Style drift: unwanted art styles, CG/plastic look, color palette bleed.
- Continuity: costume changes, new characters/props, changing face/hair.
- Motion: static openings, jitter, contradictory camera moves.
- Clipping: fabric through body, weapons/props detaching or vanishing.
- Content: text, logos, watermarks, elements the concept explicitly forbids.

Mirror the source material's own 禁止项 when the input is a video-analysis document — those lists already encode the author's hard boundaries.

## 7. Genre / style adaptation

- Take the target visual style as a **lock** and apply it uniformly: name the medium (ink-wash, anime, photoreal, film grain), the palette, the lighting character, and the render quality once, then restate in each segment.
- Adapt camera/motion vocabulary to the genre (e.g. sweeping calligraphic ink trails + dutch/low angles for wuxia; shallow DOF + steady moves for portrait/editorial; high-contrast + fast whips for action).
- Preserve the source intent when translating a video-analysis document; only reframe for the model, never contradict it.

## 8. Timelines and structure

- **Temporal anchoring.** Every clip has an exact duration in seconds, tagged `[MM:SS - MM:SS]`; the per-clip durations must sum exactly to the target duration. Internal shots are tagged `[Shot N] At MM:SS.mmm` relative to the segment's own start (0:00).
- Timestamps must be numerically consistent and sum to the target duration.
- **Push each segment to the per-clip budget: 12–15s, settling to 10–14s only when the beat can't sustain 15s. Never split the timeline into throwaway 2–3s segments** — longer segments also mean fewer cuts for the model to render cleanly.
- Every segment must earn its place — no filler, no dead static holds.
- Plan a clear visual progression (e.g. establish → build → climax → resolve) and a clean transition into/out of each segment.
- **Join segments with cinematic cuts (j-cut / l-cut / straight-cut / match-cut) on contrasting compositions** (see §5C) — never by feeding one clip's final frame into the next.
- Build to a climax and land a clean ending; don't decay intensity early.

## 9. Resolution and aspect ratio control

H3 output is controlled by the workflow, not by ad-hoc custom dimensions:

- **Aspect ratio:** node `7893` (`easy boolean`) — `false` = 9:16 (portrait), `true` = 16:9 (landscape).
- **Resolution:** nodes `6073` (phase-1 composition) and `6074` (phase-2 upscale target) are `OlmResolutionPicker` instances. The current workflow feeds `6074` into the phase-2a `MMH3UltimateUpscale` node `7569`, so `6074` sets the final render size — currently `896×1568` (1.40 MP). `render_h3.py` leaves both untouched. Node `7718` and the phase-2b upscale chain were removed from the workflow.
- The native render is the deliverable; add a post-processing scale only when the user explicitly asks for one.

## 10. ComfyUI queue checking (always check before submitting)

Before submitting any H3 or image-generation prompt, check ComfyUI's queue state:

```bash
# Check current queue state
curl -s http://127.0.0.1:8188/queue | jq '{queue_running: (.queue_running | length), queue_pending: (.queue_pending | length)}'

# Quick busy check
RUNNING=$(curl -s http://127.0.0.1:8188/queue | jq '.queue_running | length')
if [ "$RUNNING" -gt 0 ]; then
  echo "ComfyUI is busy ($RUNNING job(s) running)!"
else
  echo "ComfyUI is idle."
fi
```

**Polling after submission:** After POSTing a prompt, do NOT immediately check `/history` — the prompt may still be queued behind existing jobs. Instead:

1. Record the `prompt_id` returned from the POST to `/prompt`.
2. Poll `/queue` in a loop until both `queue_running` and `queue_pending` are empty (idle).
3. Then poll `/history` filtering for your specific `prompt_id`.
4. For H3 video, look for output from the `SaveVideo` node (node 447 in the standard workflow).

```bash
# Wait for idle, then check history for our prompt
PROMPT_ID="your_prompt_id_here"
while true; do
  RUNNING=$(curl -s http://127.0.0.1:8188/queue | jq '.queue_running | length')
  PENDING=$(curl -s http://127.0.0.1:8188/queue | jq '.queue_pending | length')
  if [ "$RUNNING" -eq 0 ] && [ "$PENDING" -eq 0 ]; then
    echo "Queue idle. Checking history..."
    break
  fi
  echo "Waiting... running=$RUNNING pending=$PENDING"
  sleep 10
done
curl -s http://127.0.0.1:8188/history/$PROMPT_ID | jq '.[$PROMPT_ID] | keys'
```

**Important notes:**
- ComfyUI's history is cleared between sessions/generations, so stale prompt IDs may not be found.
- The `SaveVideo` node (447) saves MP4 files to `output/video/claude_code/` inside the ComfyUI directory.
- **Reference images must be in ComfyUI's `input/` directory** (`~/Documents/comfyui/input/`). The `LoadImage` node cannot traverse outside this folder — if a reference image is placed elsewhere (e.g. in `outputs/`), the node will fail. Copy images to `input/` before submitting: `cp outputs/*.png ~/Documents/comfyui/input/`.
